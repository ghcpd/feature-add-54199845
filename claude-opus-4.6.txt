````
After upgrading to the latest version of requests, I'm seeing a strange behavior with header validation. Now it seems to silently accept it and tries to send the request anyway, which then blows up deeper in the stack with a `ValueError: Invalid header value` from what looks like Python's own HTTP internals.

I also noticed that header names with a trailing newline (like `"foo\n"`) are no longer caught either.

```python

My environment:
- Python 3.10
- requests latest from main branch
- Ubuntu 22.04

Maybe the validation regex was changed recently? I'm not sure what could cause newlines at the very end to be treated differently from newlines in the middle of a value (those are still correctly rejected).
````

### 💬 Copilot

Found the bug. In Python regex, `$` matches before a trailing newline by default. So `"bar\n"` passes validation because `$` matches before the `\n`. The fix is to use `\Z` (absolute end of string) instead of `$`.
